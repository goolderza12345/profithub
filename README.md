# ProfitHub

ระบบวิเคราะห์กำไรสำหรับผู้ขายออนไลน์ในประเทศไทย (MVP 1.0)

- **Next.js 16** (App Router) + TypeScript + Tailwind CSS 4
- ข้อมูลเก็บในเบราว์เซอร์ผ่าน **IndexedDB** (ไลบรารี `idb`) ไม่มีเซิร์ฟเวอร์หรือฐานข้อมูลภายนอก
- ข้อมูลจริงและ Demo อยู่คนละฐานข้อมูล (`profithub-real` / `profithub-demo`)
- ไลบรารี open source: `papaparse` (CSV), `recharts` (กราฟ), `lucide-react` (ไอคอน), `vitest` (ทดสอบ)

## ความปลอดภัยของข้อมูล (v1.1)

- **Backup/Restore:** ไฟล์ JSON มี checksum, ตรวจทุกรายการก่อนกู้คืน, ห้ามกู้คืนข้ามชุด (จริง ↔ Demo), เขียนใน transaction เดียว (ล้มเหลว = ข้อมูลเดิมอยู่ครบ)
- **จุดกู้คืนอัตโนมัติ:** เก็บสำเนาล่าสุด 5 จุดก่อนกู้คืน ลบชุดนำเข้า หรือลบข้อมูลทั้งหมด
- **Historical Cost Snapshot:** รายการขายบันทึกต้นทุนต่อชิ้น ณ วันนำเข้า การแก้ต้นทุนภายหลังไม่กระทบกำไรย้อนหลัง (ข้อมูลจาก v1.0 ถูกเติม snapshot ด้วยต้นทุนปัจจุบันตอนอัปเกรดฐานข้อมูล)
- **ตรวจข้อมูล:** จำกัดความยาว/ขนาดตัวเลข/จำนวนแถว, กันรายการซ้ำ 2 ชั้น (ตอนตรวจไฟล์ + unique index), ป้องกัน CSV formula injection ในไฟล์รายงาน

สูตรคำนวณทั้งหมดอยู่ใน `src/lib/profit.ts` (ดูคำอธิบายด้านบนไฟล์)

## Smart Import (v1.2)

ขั้นตอน: เลือกแหล่งข้อมูล + ไฟล์ → จับคู่คอลัมน์ → ตรวจสอบ/จับคู่สินค้า → ยืนยัน → สรุปผล

- **ไฟล์:** CSV (UTF-8, UTF-8 BOM, UTF-16, Windows-874) และ Excel `.xlsx` (อ่านด้วย `read-excel-file` MIT) — ไม่รองรับ `.xls` รุ่นเก่า, ไม่เกิน 10 MB / 20,000 แถว
- **แหล่งข้อมูล (adapters)** อยู่ที่ `src/lib/import/adapters/`
  - `generic` — ใช้งานได้จริง (แม่แบบ ProfitHub จับคู่อัตโนมัติ, ไฟล์อื่นจับคู่คอลัมน์เอง)
  - `shopee`, `tiktok`, `lazada` — **โครงสร้างเตรียมไว้ ยังไม่ได้ทดสอบกับไฟล์ส่งออกจริง** ระบบแจ้งผู้ใช้และบังคับให้ยืนยันการจับคู่คอลัมน์เอง
  - วิธีเพิ่มรูปแบบที่ยืนยันแล้ว: ได้ไฟล์ตัวอย่างจริง (ลบข้อมูลส่วนตัว) → ใส่ชื่อคอลัมน์ใน `verifiedHeaders` → เพิ่ม unit test กับไฟล์นั้น → ตั้ง `verified: true`
- **กันหักซ้ำ:** ค่าที่ไฟล์แสดงซ้ำทุกบรรทัดของคำสั่งซื้อ ตั้งเป็น “ทั้งคำสั่งซื้อ” แล้วระบบปันส่วนตามยอดขาย (ระบบเตือนเมื่อพบรูปแบบนี้)
- **ไม่มีข้อมูล ≠ ศูนย์:** คอลัมน์ที่ไม่มีในไฟล์ถูกบันทึกใน `Sale.missingFields` และผลลัพธ์แสดงเป็น “กำไรโดยประมาณ”
- **จับคู่สินค้า:** SKU ที่ไม่พบเป็น “รอจับคู่” ผู้ใช้เลือกสินค้าเดิม (ระบบจำไว้ใน `skuAliases`) หรือยืนยันสร้างสินค้าใหม่เอง
- **ความปลอดภัย:** บันทึกใน transaction เดียว + จุดกู้คืนก่อนนำเข้า, กันซ้ำด้วย ช่องทาง+เลขคำสั่งซื้อ+SKU และเตือนเมื่อเป็นไฟล์เดิม (checksum)
- ฐานข้อมูล v3 (ย้ายข้อมูลจาก v1/v2 อัตโนมัติ), ไฟล์ Backup schema 2 (กู้คืนไฟล์ schema 1 ได้)

## คำสั่ง

```bash
npm install
npm run dev     # http://localhost:3000
npm test        # unit tests (สูตรกำไร, CSV/XLSX, การจับคู่คอลัมน์, การตรวจข้อมูล, รายการซ้ำ, Backup, IndexedDB)
npm run test:e2e  # E2E ขั้นตอนนำเข้าบนจอมือถือ (Playwright; ต้องมี Chromium ของ Playwright 1.63)
npm run lint
npm run build
```

## รูปแบบไฟล์ CSV ยอดขาย

```
order_id,order_date,channel,sku,quantity,unit_price,discount,refund,returned_qty,platform_fee,shipping_fee
```

คอลัมน์ 6 ตัวแรกบังคับ ที่เหลือว่างได้ (= 0) · วันที่รองรับ `YYYY-MM-DD` และ `DD/MM/YYYY` (พ.ศ. ได้) · รายการซ้ำตัดสินจาก ช่องทาง + เลขคำสั่งซื้อ + SKU
